- 基于 HolyCrab CLI v0.5.0 / `48126baa08521961de47d48bd2134c44a7e8cba2`，独立分支 `codex/cli-v060-reliability`。

- 沿用 2026-10-09 的 12 模型能力快照。未修改后端、计费或 API 地址。
- 保留启动器路径、既有 CLI 命令与 MCP 输入字段；新增一个本地只读命令和一个 MCP 工具，合计 32 个 CLI 叶子命令、21 个 MCP 工具。

## 更新通知补齐与独立复查

- 更新检查成功缓存 24 小时，失败后 1 小时重试；同一新版每天最多提示一次，更高版本可重新提示。跨进程非阻塞锁避免同时启动重复请求与提醒。
- MCP 长进程在工具调用前按相同缓存周期刷新；提示放在独立 content 和元数据，业务 structuredContent/isError 不改变。Agent 按 Skill 要求简短告知，同会话去重，不自行升级。
- 只读/损坏/过期缓存安全降级；禁用变量同时关闭自动联网和自动提醒；显式检查仍有效。超长版本值不能破坏 MCP 初始化。
- 独立审查发现并修复：Windows 持锁卸载误报成功和误清理数据、下载提前 EOF 被报成功、safe live smoke 的两个失效拦截器、旧 Windows/发布测试清单，以及旧版本号读取路径。
- 重写本地 lifecycle 演练为完整临时 HOME；没有真实账号、用户安装或在线写入。历史 live 脚本改为显式专用账号/凭据/素材和写入授权，未完成任务返回 2，不再误报通过。
- 默认验收入口 `python3 tools/run_checks.py`：自动发现新测试、隔离配置、拒绝未替换的 Python 网络请求、终止超时进程树、区分失败/跳过/未具备条件、记录源码和测试指纹。全跳过和空测试集失败退出。安装子进程也使用所选 Python 版本。
- 测试数据显式替换 DNS，但继续执行真实 URL 安全校验。安装器/公开运行时没有 Mock 模式，测试依赖仍不进入安装包。

## 发布顺序与网站交接

1. 处理能力快照差异，重新跑相关契约和行为测试；不要改变已有模型约束来迎合测试。
2. 在可审阅的候选提交上完成原生矩阵与获授权的真人验收，记录当前 `candidateSha256`；候选源文件再次改变必须重新判断验收有效性。
3. 测试分支提交与 CI 已获批准；版本标签与 Release 必须等待另行批准。Draft Release 的源提交、安装器字节、GitHub digest 和三平台安装检查必须一致；禁止覆写同版本资产。
4. 手动工作流默认只准备/复核 Draft；只有明确选择 `publish_release: true` 且所有依赖成功才公开为 Latest。
5. 正式 Release 验证后，再同步网站版本数据和版本化安装器，补五语言上传记录查询说明；最后验证稳定入口确实指向该正式版本。本次不改 `public/cli` 或网站 release 数据。

## 使用与恢复边界

- 新增 `holycrab assets uploads get PLAN_ID` / MCP `asset_upload_plan_get`。
- `isError: true` 和 `localStateSaved: false` 都不意味着可以重试写入；优先保存并查询已知 ID。
- 上传临时磁盘需求等于完整批次字节总量；临时流关闭即清理，内存按块使用。
- 不可解释或已执行的记录保留，避免丢掉防重凭据；需要用户决定的历史记录清理不在本次范围内。
- 强制杀死安装进程可能遗留 `.holycrab-install.lock` 目录。确认进程结束、检查回滚备份后才能人工解除；普通退出会释放锁。
- 卸载保留用户改动和额外文件；无法确认的 Agent 登记会报告 pending。已修改启动器会阻止卸载，避免误删。
