# v0.6.0 素材合同与 Berry 同步

本次在既有 v0.6.0 未发布候选上同步服务端素材合同，并补齐四个 Berry 型号。后端基线为远端 main `569aa948d5ea70c15ce719783e71935d02309743`；源文件通过不可变 Git blob 提取，未切换或修改后端工作区。测试分支提交和 CI 已获授权；合并、打标签、Release 和网站发布仍未获授权。

## 行为

- 16 模型能力快照（2026-10-23）；Berry 使用独立生成/估算路由及 DTO 默认值。
- CLI 保留请求结构、输出参数和本地文件完整性检查；后端统一判断素材的归属、数量、组合、格式、大小、尺寸、帧率、编码和引用标记。一次上传仍限制 10 个文件，属于操作批次限制。
- API 错误保留结构化 errors、实际值和限制，CLI/MCP 统一显示和脱敏；旧 message-only 返回兼容。retryable 不会自动触发写入。
- 素材查询增加精确元数据和状态。元数据未知、处理中或失败不由 CLI 额外拦截，ready 只表示原处理状态。
- 增加单次显式元数据重试命令及 MCP 工具；HTTP 成功不保证状态改变或已完成探测。
- 图片增加素材 ID、非空 ID 优先；音频支持素材 ID/type 和 URL，旧 inline/speaker 格式提示显式上传迁移。音频估算携带完整请求体。

## 验证与证据

统一入口、不可变源码提取和证据命令见 [自动化验收](automated-testing.md)。本地严格契约检查通过才写入当前候选证据，绑定后端提交、源文件哈希、验证器和候选指纹；CI 只检查记录证据，明确不声称实时读取后端。证据 7 天过期，候选内容改变立即失效。

源码规则反例覆盖后端 Berry 时长边界改动、结构化实际值字段丢失、CLI 重加素材数量限制及音频 ID 支持丢失；证据测试覆盖脏工作区、篡改、缺输入、过期及候选漂移。详细执行结果和三平台 CI 记录将保存在 build/validation/ 与草稿 PR #8。

真人流程验收保持 pending，正式发布等待用户确认；所有默认测试均在隔离环境运行，没有真实上传、真人授权或付费生成。
