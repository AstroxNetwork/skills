## 清理清单

- 删除 `holycrab/scripts/holycrab_api.py` 及其独立 polling/upload 入口；当前指引和 CI 不再引用。
- `auth set-key`、`credits estimate` 保留隐藏兼容，与 `setup`、`generate estimate` 共用实现；当前帮助和示例不推荐旧名称。
- 按配置目录节流 QR 过期扫描 5 秒，失败不阻断查询；授权终态立即删除 QR，不受扫描节流影响。
- 能力文件与模型索引在单次命令/MCP 调用内共享，返回深拷贝；结束或异常时释放。账号响应没有缓存。
- setup、账号状态、余额、online doctor 与 MCP account_get 共用账号边界；保留各入口错误、公开字段及环境变量覆盖语义。
- 删除未使用导入与重复 attempt ID 兜底，统一 MCP/安装后 Agent 引导规则；保留 onboarding 字段。
- 离线 doctor 的 CONFIGURED 仅表示本地已有 Key，不表示验证失败或账号已经连接。已有同对话有效验证时，Agent 不因离线 doctor 要求重复验证。
- 测试、Mock、fixture、烟测驱动和测试依赖迁到顶层 `tests/`；开发验证器迁到 `tools/`。

## 旧安全测试迁移

原旧辅助脚本 22 项测试中，10 项改为测试主 CLI；12 项重复覆盖由下列更完整的现有测试保留。另增加 21 项清理、指引、安装白名单及发布验收检查：307 − 22 + 10 + 21 = 316。

| 原覆盖 | 当前实际运行代码的覆盖 |

| HTTPS 上传地址、危险协议及嵌入凭据拒绝 | test_transport_security |

登记失败时，现实现保留已知资产 ID 用于恢复查询，并明确 state=failed；不会把它作为上传成功结果。这不是恢复旧脚本“丢弃已知 ID”的行为。

## 发布顺序已固化，当前不得继续

发布工作流保持所有必需 needs；只有标签触发，且手动验收记录明确通过后才创建 Draft。校验 GitHub digest/下载字节后，在三个原生系统安装 Draft 文件；全部成功才发布为 Latest。任何阶段失败，不覆盖既有资产，也不自动晋级。

当前 `docs/release-acceptance/v0.4.3.json` 明确 pending；运行 verify_release_acceptance 会拒绝发布。测试中使用的 passed fixture 不会写入真实验收记录。

继续发布前需要：

1. 为 CLI CI 配置有权只读 Generate 私库的 `GENERATE_CONTRACT_SSH_KEY`，重新跑必需契约检查。本轮没有创建、复制或上传凭据。
2. 用户完成真人授权→确认人物分组→选文件→完整预览→确认上传→等待可用的实际验收，并记录不含姓名、Key、私密链接或 QR 的结果。
3. 全部必需检查通过后，合并 CLI、创建新标签/Draft、校验并发布，再逐字节同步官网及更新真实发布日期，最后部署。
4. 完成官网新机 Mac/Windows 烟测与隔离旧版正式 update。尚未执行的项目不能提前打勾。
