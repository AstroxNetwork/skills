# Voiceover
Use for product narration, explanatory speech and a user's script. Read execution.md first.

Preserve the approved wording, language, pronunciations and explicit voice/performance preferences. If the user asks you to write the script, keep factual claims grounded in their materials. Read long numbers and product names in a spoken form only when it preserves meaning. Estimate pacing against the available time; do not promise exact word-level alignment.

Discover the current audio capability and request schema. Respect modelFieldInRequest, supported formats, sample rates and reference rules. A reference voice is user-selected material, not permission to upload unrelated files or to claim a voice-cloning feature. Use the model's required reference labels. Pure text narration should not fabricate references.

Confirm uploads separately, show the actual generation estimate, create once, query and download. If sound is needed for a video, make it a workflow dependency. Probe the actual duration before composition; if narration exceeds the planned slot, stop for a revised script or an explicit trim rather than silently cutting speech.

This workflow does not add a music generator, speech recognition or lip-sync API. For background music use a selected existing local file; for subtitles use a supplied SRT/ASS or approved segment text and times.

Example: “Read this introduction in natural Mandarin.” Preserve the introduction, choose supported speech options, estimate, confirm and generate. “Rewrite this introduction” only returns text.
